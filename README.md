# 🎃 Хоррор-сервер Minecraft 1.20.1 (Docker)

Простой сервер под вашу хоррор-сборку: клонируешь репо на ВДС, кидаешь зип сборки — и `docker compose up -d`. Всё.

## ⚠️ Сначала про 1 ГБ RAM — честно

Моды на ~800 МБ на версии 1.20.1 хотят **2–4 ГБ** оперативки. На 1 ГБ сервер, скорее всего, запустится (здесь всё настроено под малую память: 768 МБ + свап + лёгкие флаги), но мир будет грузить, возможны лаги и краши.

**Оптимум — апгрейдить ВДС до 4 ГБ.** Тогда просто поменяете в `.env` строку `MEMORY=3G` и перезапустите. Больше ничего менять не надо.

Чтобы даже на 1 ГБ сервер жил, один раз создайте **свап** на ВДС:

```bash
sudo fallocate -l 3G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## Запуск (по шагам)

**1. Docker** (если на ВДС его нет):

```bash
curl -fsSL https://get.docker.com | sudo sh
```

**2. Клонируешь репо:**

```bash
git clone https://github.com/dyxoalt-tech/Danil4LENbolshoy.git mc
cd mc
```

**3. Кидаешь сборку.** Берёшь тот самый зип пака (который ставишь на клиент) и кладёшь в папку `pack/` на ВДС с именем `pack.zip`:

```bash
# с домашнего компа (свой IP ВДС подставь):
scp путь/к/сборке.zip user@IP_ВДС:~/mc/pack/pack.zip
```

**4. Проверяешь `.env`** — две вещи:

- `MC_VERSION` — версия как у сборки (сейчас `1.20.1`);
- `MOD_LOADER` — `forge` или `fabric`. Как узнать: открой зип пака, глянь в папку с модами: есть файл `mods.toml` → `forge`, `fabric.mod.json` → `fabric`.

**5. Запуск:**

```bash
docker compose up -d
```

Первый запуск будет долгим — контейнер качает сам сервер и распаковывает все моды. Смотришь лог:

```bash
docker logs -f minecraft
```

Когда в логе появится **`Done`** (и `Starting minecraft server version 1.20.1`) — можно заходить.

**6. Пожаркаль** (если на ВДС стоит UFW):

```bash
sudo ufw allow 25565/tcp
```

**7. Вход.** В Minecraft: Multiplayer → Add Server → `IP ВДС` (порт 25565 подставится сам) → играешь на той же версии, с той же сборкой. Другу отправляешь IP — заходит так же.

## Пригодные команды

```bash
docker compose logs -f     # логи (Ctrl+C — выйти из лога)
docker compose stop        # остановить
docker compose start       # запустить снова
docker compose restart     # перезапустить
docker compose pull && docker compose up -d   # обновить образ сервера

# удалить сервер полностью (МИР ТОЖЕ ПРОПАДЕТ, если не скопировал data/):
docker compose down && rm -rf data/
```

Мир хранится в папке `data/` — хочешь, забери его на комп: `scp -r user@IP_ВДС:~/mc/data/ .`

## Обновить моды / сменить сборку

Замени `pack/pack.zip` новым зипом, удали старый мир (если версия изменилась) и перезапусти:

```bash
docker compose down
rm -rf data/ mods/
docker compose up -d
```

## Если что-то пошло не так

| Симптом | Лечение |
|---|---|
| Сервер упал / "Killed" в логах | Не хватает RAM: увеличь свап до 4–5 ГБ или апгрейдни ВДС и подними `MEMORY` |
| Ошибка про MOD_LOADER при старте | Переключи `MOD_LOADER` в `.env` на `fabric`/`forge` (что не стоит) и `docker compose up -d` |
| Не подключается | Проверь: порт 25565 открыт (шаг 6), IP верный, в клиенте та же версия 1.20.1 и та же сборка |
| Долго висит на старте | Просто качает/распаковывает 800 МБ модов на первом запуске, дай 10–20 минут |
| Ошибка Java | Поменяй `JAVA_VERSION` в `docker-compose.yml` на `21` (для новых версий) или `17` (для 1.20.1) |

## Структура

```
├── docker-compose.yml   # описание контейнера
├── .env                 # версии, память, загрузчик модов — всё крутится тут
├── pack/                # сюда кладёшь pack.zip со сборкой (в git не коммитится)
└── data/                # мир + конфиги (создаётся сам, в git не коммитится)
```
